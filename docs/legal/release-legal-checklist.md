# Tripic 배포 전 정책·개인정보 체크리스트

이 문서는 공개 정책이 아니라 배포 담당자가 확인할 내부 체크리스트다. 정책 문서만 만들어서는 심사와 법적 준비가 끝나지 않는다.

## 2. 출시를 막는 필수 확정사항

- [ ] 운영자명 또는 상호, 대표자, 주소, 고객지원 연락처를 확정한다.
- [ ] 개인정보 보호책임자와 위치정보관리책임자 또는 담당 부서를 지정한다.
- [ ] 최초 시행일을 실제 출시일로 교체한다.
- [ ] 모든 `[대괄호]` 문구를 실제 정보로 교체하고 초안 안내문을 제거한다.
- [ ] 개인정보 처리방침을 로그인 없이 열리는 공개 HTTPS URL에 게시한다.
- [ ] 앱 설정 화면에서 개인정보 처리방침과 서비스 이용약관을 언제든지 열 수 있게 한다.
- [ ] 최초 이용 또는 필요한 기능 실행 전에 약관 동의 상태와 버전을 기록하는 방식을 확정한다.
- [ ] 앱의 “개별 기록 삭제”와 “전체 기록 초기화” 기능을 실제로 구현하고 검증한다.

## 3. 사진 EXIF GPS에 관한 중요 확인

현재 설계는 GPS 좌표를 Tripic 백엔드로 보내지 않지만, 앱이 한국관광공사 OpenAPI에 직접 보내도록 되어 있다. 따라서 “위치정보는 기기 밖으로 전송되지 않는다”라고 안내하면 안 된다.

- [ ] 사용자가 사진을 선택하기 전에 사진 접근 목적을 알기 쉽게 안내한다.
- [ ] GPS가 있는 사진에서 후보 검색을 실행하기 직전에 “좌표가 한국관광공사 TourAPI로 전송된다”는 사실, 목적, 거부 방법을 고지한다.
- [ ] 동의하지 않은 이용자에게 직접 검색·지역 선택 등 실질적인 대체 흐름을 제공한다.
- [ ] 사진 원본과 EXIF 전체가 전송되지 않고 필요한 위도·경도와 검색 조건만 전송되는지 네트워크 요청을 검사한다.
- [ ] GPS 좌표가 로그, 오류 리포트, 분석 SDK, 로컬 데이터베이스 또는 Tripic 서버에 남지 않는지 검사한다.
- [ ] TourAPI 또는 공공데이터포털이 좌표·IP·요청 기록을 보유하는지 공식 답변이나 약관으로 확인하고 정책 및 스토어 답변에 반영한다.
- [ ] 사진 EXIF GPS 이용이 위치정보법상 개인위치정보 이용·제공 또는 위치기반서비스사업에 해당하는지 전문가나 관할 기관에 확인한다.
- [ ] 해당한다면 사업 신고, 위치정보 이용약관, 별도 동의, 이용·제공사실 확인자료 기록·보존·파기와 제3자 제공 통보 절차를 구현한다.

위치정보법 제9조는 개인위치정보를 대상으로 하는 위치기반서비스사업의 신고를 규정하고, 제9조의2는 소상공인·1인 창조기업의 신고 시기를 별도로 규정한다. 제19조는 위치기반서비스 제공 전에 이용약관 기재와 동의를 요구한다. 앱의 구체적인 데이터 흐름에 대한 적용 여부는 문서만으로 단정하지 않는다.

## 4. 프로덕션 데이터 흐름 확인

- [ ] 출시 빌드에 포함된 모든 SDK와 네이티브 권한을 목록화한다.
- [ ] Expo·React Native 패키지의 프로덕션 데이터 수집 여부와 플랫폼 개인정보 매니페스트를 확인한다.
- [ ] Sentry, Firebase, PostHog, 광고, 푸시, 고객지원, CDN 또는 로그 서비스가 추가되면 정책을 먼저 갱신한다.
- [ ] NestJS 운영 API의 호스팅 사업자, 서버 위치, IP·요청 로그 항목과 보유기간을 확정한다.
- [ ] 운영 API에서 GPS, 사진, EXIF, 방문 기록, 검색어를 수신하지 않는지 E2E 또는 프록시 로그로 검증한다.
- [ ] 모든 API 통신이 HTTPS인지 확인한다.
- [ ] 개인정보나 GPS가 URL 쿼리, 크래시 로그, 콘솔 로그에 노출되지 않게 한다.
- [ ] 개인정보 처리업무 위탁 또는 국외 이전이 생기면 수탁자·국가·항목·목적·기간·거부 방법을 처리방침에 추가한다.

## 5. Apple App Store 제출

- [ ] App Store Connect에 공개 개인정보 처리방침 URL을 입력한다.
- [ ] 앱 안에서도 개인정보 처리방침을 쉽게 열 수 있게 한다.
- [ ] App Privacy 답변에 앱과 포함된 제3자 코드의 데이터 처리를 모두 반영한다.
- [ ] 사진 원본과 여행 기록이 기기 안에서만 처리되는지 확인한다. 온디바이스 처리만 한다면 Apple의 “수집” 정의에는 일반적으로 포함되지 않는다.
- [ ] GPS 좌표의 TourAPI 전송이 실시간 요청 처리 후 보유되지 않는지 확인한다. Apple은 요청 처리에 필요한 시간보다 길게 외부에서 접근 가능한 경우를 “수집”으로 정의하므로, 외부 보유 여부를 모르는 상태에서 “수집 안 함”으로 답하지 않는다.
- [ ] 사진 권한 목적 문자열에 선택 사진의 촬영일시·위치정보 사용 목적을 구체적으로 적는다.
- [ ] 추후 계정 생성 기능을 넣으면 앱 안에서 계정 삭제도 제공한다.

## 6. Google Play 제출

- [ ] Play Console에 공개 개인정보 처리방침 URL을 입력하고 앱 안에서도 정책을 제공한다.
- [ ] Data safety 양식을 모든 프로덕션·공개/비공개 테스트 배포 범위에 맞게 작성한다.
- [ ] Google Play에서 기기 밖으로 전송되는 GPS는 “정확한 위치” 항목 검토 대상이다.
- [ ] GPS와 검색어가 요청 처리에 필요한 동안만 메모리에 있고 즉시 폐기되는지 외부 제공기관에 확인한다. 조건을 충족하면 ephemeral processing으로 신고할 수 있지만, 양식에서 해당 데이터 전송 자체는 정확하게 답해야 한다.
- [ ] 검색어를 외부 API로 보내므로 “앱 내 검색 기록” 데이터 유형 해당 여부를 확인한다.
- [ ] 사진이 기기 밖으로 전송되지 않는다면 Data safety의 수집 항목에 포함되지 않는지 실제 빌드로 검증한다.
- [ ] 일회성·제한적 사진 선택만 필요하므로 광범위한 사진 권한 대신 시스템 사진 선택기를 사용하는지 Android 매니페스트와 실기기에서 확인한다.
- [ ] 대상 연령과 아동 대상 여부를 실제 서비스 정책에 맞게 설정한다.

## 7. 공개와 변경 관리

- [ ] Markdown을 공개 웹페이지로 변환하고 모바일에서 읽기 쉬운지 확인한다.
- [ ] URL이 지역, 로그인, 쿠키 동의 또는 앱 설치 여부와 무관하게 열리는지 확인한다.
- [ ] 앱 버전, 정책 버전, 공고일, 시행일을 관리한다.
- [ ] 데이터 처리나 SDK가 바뀌면 코드 배포 전에 정책과 스토어 답변을 갱신한다.
- [ ] 이전 정책을 날짜별로 보관하고 변경 내용을 공지한다.
