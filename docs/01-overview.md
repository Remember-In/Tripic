# 01. 제품 개요 · 배경 · 목표 (PRD 1~3장)

> 원문: [00-prd-full.md](./00-prd-full.md) · 인덱스: [README.md](./README.md)

## 1. 제품 개요

### 1.1 한 줄 정의

사용자가 촬영한 여행 사진을 선택하면, 사진의 위치 정보를 앱 내부에서 확인하고 한국관광공사 OpenAPI를 실시간 호출하여 주변 관광지 후보를 찾은 뒤, 방문 기록 카드와 대한민국 여행 지도를 생성하는 모바일 앱.

### 1.2 제품 비전

“사진 한 장이 곧 여행 기록이 된다.”

사용자는 여행 중 촬영한 사진을 선택하는 것만으로 방문 장소 후보를 확인하고, 한국관광공사 공공데이터와 연결된 여행 기록을 만들 수 있다. 서비스는 여행 기록을 지도 위에 스탬프처럼 쌓아가며, 장기적으로 AI 해설·미션·뱃지·추천으로 국내 여행의 재미와 동기를 높인다.

### 1.3 P0 핵심 가치 제안

| 가치                       | 설명                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| 사진 기반 기록             | 사용자가 찍은 사진을 여행 기록의 시작점으로 사용                                      |
| 위치 기반 관광지 후보 추천 | 사진 EXIF GPS를 앱에서 확인하고, 관광공사 OpenAPI로 직접 전송해 주변 관광지 후보 조회 |
| 사용자 확정 기반 기록      | 자동 확정이 아니라 사용자가 실제 방문지를 선택/수정하여 기록 정확도 확보              |
| 지도 스탬프                | 방문한 관광지의 지역 정보를 바탕으로 대한민국 지도에 방문 현황 표시                   |
| 공공데이터 실시간 활용     | 관광지명·주소·소개·이미지·지역/분류 정보를 관광공사 OpenAPI 실시간 호출로 활용        |
| 위치정보 리스크 최소화     | 사용자 GPS를 Tripic 백엔드나 로컬 DB에 저장하지 않고 TourAPI 후보 조회에만 활용       |

## 2. 배경 및 문제 정의

여행자들은 방문 장소를 사진으로 남기지만, 사진을 다시 정리하고 장소명·방문일·설명을 수동 입력하는 과정은 번거롭다. 그 결과 여행 사진은 갤러리에 흩어지고 개인의 여행 경험이 체계적 기록으로 이어지지 못한다. 한편 한국관광공사 OpenAPI에는 풍부한 관광 데이터가 있지만 일반 사용자가 직접 체감할 서비스 경험은 제한적이다.

본 서비스는 사용자의 여행 사진과 관광공사 데이터를 연결하여 사진을 의미 있는 여행 기록으로 전환한다. P0에서는 다음 문제 해결에 집중한다.

1. 사진 위치 정보로 주변 관광지 후보를 쉽게 찾을 수 있는가?
2. 사용자가 후보 중 실제 방문지를 선택해 기록을 만들 수 있는가?
3. 생성된 기록이 지도 위에 쌓이며 여행 동기를 줄 수 있는가?
4. 관광공사 OpenAPI가 실제 사용자 플로우에서 실시간 활용되는가?
5. 사용자 GPS가 백엔드 서버로 전송되지 않는 구조를 유지할 수 있는가?

## 3. 목표 및 제외 목표

### 3.1 P0 목표

1. 사용자는 iOS/Android 앱에서 여행 사진을 선택할 수 있다.
2. 앱은 사진의 EXIF GPS와 촬영일시를 단말기 내부에서 확인할 수 있다.
3. 앱은 GPS 좌표 기반으로 관광공사 OpenAPI를 직접 호출하여 주변 관광지 후보를 조회한다.
4. 사용자는 후보 중 실제 방문지를 선택/수정할 수 있다.
5. 확정한 관광지와 사진을 바탕으로 여행 기록 카드가 생성된다.
6. 방문 기록은 지도 스탬프로 반영된다.
7. P0에서는 GPS 좌표를 Tripic 백엔드 서버로 전송하지 않고, 위치 기반 조회 시 한국관광공사 OpenAPI로만 직접 전송한다.
8. P0에서는 OpenAPI 데이터를 로컬/서버 DB에 저장하여 서빙하지 않는다.
9. P0에서는 서버 DB와 ORM 없이 구현한다.
10. NestJS 서버는 공지·약관·앱 설정·버전 체크 등 비위치성 운영 기능에 한정한다.

### 3.2 P1 목표

1. GPS 없는 사진의 키워드 검색/지역 선택 기반 기록 생성 플로우 고도화.
2. 기록 수정/삭제 UX 안정화.
3. 지도 화면과 지역별 진행률 개선.
4. 로컬 계산 기반 간단한 뱃지/칭호 제공.
5. AI 한 줄 해설 선택 제공.
6. 수상작 미션·이미지 유사도·서버 동기화는 정책 검토 후 확장.

### 3.3 제외 목표

**P0 제외**: 완전 자동 이미지 인식 확정, OpenAPI 데이터 로컬 저장/자체 서빙, GPS 서버 전송, 실시간 위치 추적, 서버 DB/ORM, 계정 기반 동기화, 서버 저장형 방문 기록, 대화형 AI 컨시어지, AI 여행 일기, 복잡한 개인화 추천, 수상작 미션, 소셜(피드/팔로우/댓글/DM), 예약·결제, 해외 관광지 기록.

**P1 이후 검토**: AI 한 줄 해설, 뱃지/칭호, 수상작 미션, 이미지 유사도 후보 정렬, 공유/내보내기, 계정 로그인, 서버 기록 동기화, 관리자 페이지, PostgreSQL/Prisma 도입.
